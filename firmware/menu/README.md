# menu —— OLED 多级菜单

对应赛题 **基础部分第 1 项「OLED 菜单」（6 分）**。

> **当前状态：学习阶段的第一版实现。**
> 只用 `printf` 画屏、`scanf` 读按键，在电脑上把菜单逻辑跑通，
> 目的是把「状态机」这一层彻底弄懂、能自己讲清楚。
> 硬件输出层、接口拆分、自动测试留在后面补 —— 见文末「待办」。
> 所以这一版**还不能直接上真机**，先做出大致的逻辑架构，再尝试上机。

## 赛题要求与实现对照

| 赛题要求 | 实现位置 |
|---|---|
| 上电后显示主菜单 | `main()` 进循环前先 `draw()` 一次 |
| 默认箭头指向首行 | `cursor[MAX_SCREEN]` 全部初始化为 0 |
| 按键 1、2 改变箭头指向行 | `main()` 里的 `key == 1` / `key == 2`（到边界回绕） |
| 主菜单至少四个菜单项 | `name[0][]`：LED 控制 / 信息显示 / 巡线功能 / 拓展功能 |
| 按键 3 进入当前选中的子菜单 | `key == 3` 分支，按 `child[]` 逐级前往下一层 |
| 按键 4 返回主菜单 | `key == 4` 分支，按 `parent[]` 逐级返回，并把离开那一屏的箭头清零 |

## 数据结构

菜单的**全部内容都写在文件顶部的表里，加菜单项只改表、不改逻辑**：

| 变量 | 作用 |
|---|---|
| `title[MAX_SCREEN][40]` | 每一屏的标题 |
| `name[MAX_SCREEN][4][40]` | `[第几屏][第几行]` 的菜单项文字 |
| `count[MAX_SCREEN]` | 每一屏实际有几项（决定 `draw()` 画几行） |
| `child[MAX_SCREEN][4]` | `[第几屏][第几行]` 进入第几屏； `-1`表示这一行是"动作"、不进入 |
| `parent[MAX_SCREEN]` | 每一屏按 4 退回第几屏；`-1` 表示已在主菜单、退不了 |
| `cursor[MAX_SCREEN]` | 每一屏的箭头停在**第几行**（每屏各记各的） |
| `screen` | 当前在第几屏，0 就是主菜单 |

核心思路：**屏幕上的画面一个字节都不存，只存 `screen` 和 `cursor[]` 这几个数字**。
`draw()` 每次都照着当前数字把整屏重画一遍；改数字的活全在 `main()` 里。
也就是「`main` 管数字，`draw` 管画面」。

`cursor` 做成数组而不是一个变量，是为了让每一屏各记各的箭头位置 ——
从子菜单退回主菜单时，主菜单的箭头还停在原处；而离开子菜单时它自己的箭头归零。

## 界面结构

```
第 0 屏  主菜单     LED 控制 / 信息显示 / 巡线功能 / 拓展功能
第 1 屏  LED 控制   LED1     / LED2     / 常亮     / 交替 
第 2 屏  信息显示   学号     / 版本     / 运行时间
第 3 屏  巡线功能   启动巡线 / 停止巡线 / 巡线速度
第 4 屏  拓展功能   蜂鸣器   / 舵机测试 / LED 流水灯
第 5 屏  " LED 1 "   开 / 关          ← 从第 1 屏的「LED 1」进入
第 6 屏  " LED 2 "   开 / 关          ← 从第 1 屏的「LED 2」进入
```

## 在电脑上跑

需要 `gcc` 和 `gnumake`（在 NixOS 上进入仓库根目录的 `nix-shell` 就都有了）。

```bash
make run        # 编译并运行
make clean      # 清理
```

按键：

| 键 | 作用 |
|---|---|
| `1` | 上移（首行再按会回绕到最后一行） |
| `2` | 下移（末行再按会回绕到第一行） |
| `3` | 进入选中的子菜单；已在子菜单里则执行该项 |
| `4` | 返回上一层；已在主菜单则无动作 |
| `Ctrl + D` | 退出 |

## 设计约束（来自赛题，决定了以后的架构）

赛题规定基础部分第 1～4 项**一镜到底**录制，中途不得停止、剪辑，
且**录制开始后不得修改代码、重新编译、重新烧录**。这意味着：

- **必须一份固件覆盖全部基础项**，不能按功能拆成多个工程；
- **OLED 菜单就是整个固件的顶层框架**，所有功能都从菜单进入；
- **主循环里不允许阻塞延时**（不用 `delay`），一律「定时器中断 + 状态机」。
  否则第 2 项要求的「LED 交替闪烁 30 秒 × 3 轮不停闪」、OLED 状态刷新
  和按键响应会互相干扰。

这一条也是后面必须把输出层从 `printf` 换成「填字符串 + 硬件绘制」的原因：
真机上没有 `printf`，而且刷新要由定时器驱动，不能卡在等按键上。
