# menu —— OLED 多级菜单（逻辑层）

对应赛题 **基础部分第 1 项「OLED 菜单」（6 分）**，也是第 2 项 LED 控制的入口。

> **当前状态（2026-11-05）：PC 版菜单逻辑已跑通并分层；板端还没接。**
> `menu.c` 只负责菜单表、状态机和“这一屏该显示什么”；
> 真正画到屏幕上的 `menu_render()` 由各平台自己实现：
>
> - PC：`menu_pc.c` —— `printf` 画屏、`scanf` 读键，自带 `main()`；
> - 板端：`../hw/src/menu_board.c` —— 用 OLED 画；主循环以后接在
>   `../hw/src/main.c`（现在那里还是硬件验证入口）。
>
> ⚠️ **第 2 项的按键定义和现在的通用菜单导航冲突**：赛题要求在
> **LED 控制子菜单界面**里直接按 1 / 2 / 4 控制 LED，而当前实现是
> 1/2 移动箭头、3 执行菜单项。第 2 项目前**还拿不到分**，详见下文。

## 第 1 项：菜单要求与实现（6 分）

赛题分 a、b 两小项：

| 赛题要求 | 实现位置 | 状态 |
|---|---|---|
| 1a 上电后显示主菜单 | 平台 `main()`：`menu_init()` 之后调一次 `menu_draw()` | PC 已满足；板端未接 |
| 1a 默认箭头指向首行 | `menu_init()` 把 `cursor[]` 全部清 0 | PC 已满足 |
| 1a 按键 1、2 改变箭头指向行 | `menu_key()` 的 `case 1` / `case 2`（到边界回绕） | PC 已满足 |
| 1a 主菜单至少四个菜单项 | `name[0][]`：LED 控制 / 信息显示 / 巡线功能 / 拓展功能 | PC 已满足 |
| 1b 按键 3 进入当前选中的子菜单 | `case 3`：先查 `child[screen][cursor[screen]]`，`>= 0` 就跳屏 | PC 已满足；板端未接 |
| 1b 在子菜单按 4 返回主菜单 | `case 4`：查 `parent[screen]`，`>= 0` 时把离开那屏的箭头清 0 再退 | PC 已满足（一级子菜单） |

说明：

- 第 1 项只考“主菜单 → 子菜单 → 4 回主菜单”。现在的 LED 控制、信息显示、
  巡线功能、拓展功能四屏都是主菜单的直接子屏，按 4 都能回主菜单。
- `LED 1` / `LED 2` 两屏是额外的第三层（第 5、6 屏），从它们按 4 只会回
  LED 控制，再按一次才回主菜单。赛题不要求这两屏，改第 2 项时可以保留或删掉。
- 每次按键后 `menu_key()` 置 `need_draw`，主循环用 `menu_dirty()` 判断要不要重画。

## 第 2 项：LED 要求与现状（6 分）

赛题的按键是**在 LED 控制子菜单界面里直接按**，不是“选菜单项再按 3”：

| 赛题要求 | 现在的实现 | 差距 |
|---|---|---|
| 2a 按 1：两灯常灭→常亮；再按 1：常亮→常灭 | 1/2 是移动箭头；“常亮”是 LED 控制屏的第 3 个菜单项，按 3 才执行，而且再按 3 只会重新常亮，不会切灭 | **交互不符** |
| 2b 按 2：两灯交替闪烁；3 轮 × 30 s 内不得同亮、同灭或停 | “交替”是第 4 个菜单项，按 3 才执行；`action.c` 的 `tick()` 已写好 500 ms 翻转 | **入口不符**；PC 版也没喂 `tick()` |
| 2c 按 4 返回主菜单后，两灯常灭 | `case 4` 只改 `screen` / `cursor`，不碰 LED | **未实现** |
| 2d LED 状态改变后 1 s 内，OLED 子菜单显示两灯实际亮灭 | PC 版 `show_status()` 往终端打印状态；板端 `menu_board.c` 只画标题和菜单行 | **未实现** |

> **要拿第 2 项的分，必须在 `menu_key()` 里对 `screen == 1` 单独处理**：
> 1 = 切换两灯、2 = 开始交替、4 = 回主菜单并熄灭。
> 或者把 LED 控制屏改成专用界面，不走“箭头 + 菜单项”的通用逻辑。
> 只在 `action.c` 里改是没用的 —— 按键根本到不了那里。

> 第 2 项的「测试 3 轮，每轮 30 秒」是验收方的测法：
> 测试期间不能出现同时常亮、同时常灭或闪烁停止。`tick()` 现在是一直交替、
> 不设“数够 3 轮就关灯”的分支，符合这一点。

## 数据结构

菜单的**全部内容都写在文件顶部的表里，加菜单项只改表、不改逻辑**：

| 变量 | 作用 |
|---|---|
| `title[MAX_SCREEN][LINE_LEN]` | 每一屏的标题 |
| `name[MAX_SCREEN][LINE][LINE_LEN]` | `[第几屏][第几行]` 的菜单项文字 |
| `count[MAX_SCREEN]` | 每一屏实际有几项（决定 `build()` 填几行） |
| `child[MAX_SCREEN][LINE]` | `[第几屏][第几行]` 进入第几屏；`-1` 表示这一行是“动作”、不进入 |
| `parent[MAX_SCREEN]` | 每一屏按 4 退回第几屏；`-1` 表示已在主菜单、退不了 |
| `cursor[MAX_SCREEN]` | 每一屏的箭头停在**第几行**（每屏各记各的） |
| `screen` | 当前在第几屏，0 就是主菜单 |
| `lines[LINE][LINE_LEN]` | `build()` 填好的、要交给渲染层的字符；前三个字符是 `" > "` 或 `"   "` |
| `need_draw`（`menu.c` 里的 `static`） | 1 = 需要重画；`menu_dirty()` 读一次清一次 |

三个宏在 `menu.h` 里：`MAX_SCREEN 7` / `LINE 4` / `LINE_LEN 40`。
加屏、改每屏行数只动宏，但**表要一起填满**：数组没写满时 C 会把剩下的补 0，
而 0 恰好是“主菜单”的屏号，按 4 会静默跳错一层。

核心思路：**屏幕上的画面一个字节都不存，只存 `screen` 和 `cursor[]` 这几个数字**。
`menu_draw()` 每次都 `build()` 出文字、再交给 `menu_render()` 重画整屏；
改数字的活全在 `menu_key()` 里。也就是「`menu_key` 管数字，`build` 管文字，
`menu_render` 管画面」。

`cursor` 做成数组而不是一个变量，是为了让每一屏各记各的箭头位置 ——
从子菜单退回主菜单时，主菜单的箭头还停在原处；而离开子菜单时它自己的箭头归零。

## 界面结构

```
第 0 屏  主菜单     LED 控制 / 信息显示 / 巡线功能 / 拓展功能
第 1 屏  LED 控制   LED 1   / LED 2   / 常亮     / 交替
第 2 屏  信息显示   学号     / 版本     / 运行时间
第 3 屏  巡线功能   启动巡线 / 停止巡线 / 巡线速度
第 4 屏  拓展功能   蜂鸣器   / 舵机测试 / LED 流水灯
第 5 屏  " LED 1 "   开 / 关          ← 从第 1 屏的「LED 1」进入
第 6 屏  " LED 2 "   开 / 关          ← 从第 1 屏的「LED 2」进入
```

> ⚠️ 这张表是**当前代码的实际界面**，不是赛题要求的最终形态：
>
> - 第 1 屏（LED 控制）按赛题要改成“按 1 / 2 / 4 直接控制”，
>   不能再让 1/2 只移动箭头；
> - 第 2 屏（信息显示）按第 3a 项要显示**姓名拼音 / 学号 / 变量 `a`**；
>   当前是“学号 / 版本 / 运行时间”三个菜单项，要按 3 逐条看，
>   学号还是占位值，而且缺姓名和 `a`。赛题要求在这个界面显示这三项，建议改成同屏显示。
> - 第 3、4 屏目前只是占位，第 4 项巡线和拓展还没实现。

## 文件

| 文件 | 内容 |
|---|---|
| `menu.c` | 表 + `menu_init()` / `menu_key()` / `build()` / `menu_draw()` / `menu_tick()` / `menu_dirty()`；**没有 `main()`** |
| `menu.h` | 三个宏、函数声明、`title[]` / `lines[]` / `screen` 的 `extern` |
| `menu_pc.c` | PC 的 `menu_render()`（`printf`）+ `main()`（`scanf` 读键） |
| `action.c` | 按键 3 之后做什么：LED 开 / 关 / 常亮 / 交替、电机、蜂鸣器占位；含 `tick(ms)` |
| `action.h` | `action_init()` / `do_action()` / `tick()` / `show_status()` |
| `Makefile` | `make run` 编译 `menu.c + action.c + menu_pc.c` |
| `../hw/src/menu_board.c` | 板端 `menu_render()`（OLED）；不在这个 Makefile 里 |

## 在电脑上跑

需要 `gcc` 和 `gnumake`（在仓库根目录 `nix-shell` 里都有）。

```bash
cd firmware/menu
make run        # 编译（menu.c + action.c + menu_pc.c）并运行
make clean      # 清理
```

当前 PC 版按键（**这是通用菜单的按键，不是第 2 项赛题要的 1/2/4**）：

| 键 | 作用 |
|---|---|
| `1` | 上移（首行再按会回绕到最后一行） |
| `2` | 下移（末行再按会回绕到第一行） |
| `3` | 进入选中的子菜单；已在叶子屏则执行该项 |
| `4` | 返回上一层；已在主菜单则无动作 |
| `Ctrl + D` | 退出 |

> `0` **不退出** —— 代码里没有这个分支，按了只是重画一屏。
>
> **PC 上看不到“交替”真的闪**：`menu_pc.c` 的主循环没有调 `menu_tick()`，
> 也没有真实时间源。`action.c` 的 `tick()` 已经写好（每 500 ms 翻转、永不停止），
> 板端主循环会用 `millis()` 的差值喂它。PC 上按“交替”只会看到一条
> `>> LED 交替闪烁` 和状态行 `交替=开`。
>
> 看“常亮”：`3`（进 LED 控制）→ `2` `2`（移到「常亮」）→ `3`（执行），
> 状态行会变成 `LED 1=亮 LED 2=亮`。**这只是当前菜单的操作方式，
> 不是赛题第 2 项要求的“在 LED 控制屏按 1 / 2”**。

## 设计约束（来自赛题，决定了以后的架构）

赛题规定基础部分第 1～4 项**一镜到底**，使用**同一份完整工程和同一版程序**；
录制开始后不得改代码、重新编译、重新烧录或换板，中途断录整段无效。
但**不要求按题目顺序录制**，视频里说明当前演示的是哪个小题即可；
第 5 项 Git 仓库可以单独录屏。

这意味着：

- **必须一份固件覆盖全部基础项**，不能按功能拆成多个工程；
- **OLED 菜单就是整个固件的顶层框架**，所有功能都从菜单进入；
- **主循环里不允许阻塞延时**（不用 `delay`），一律「定时器中断 + 状态机」。
  否则第 2 项的 LED 交替、OLED 状态刷新和按键响应会互相干扰。

这一条也是必须把输出层从 `printf` 换成“填字符串 + 平台绘制”的原因：
真机上没有 `printf`，而且刷新要由主循环驱动，不能卡在等按键上。
